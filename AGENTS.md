# Overview
`node-whisper-cpp` is an npm packages which builds and publishes native `whisper.cpp` binaries, plus a TypeScript package that uses a Node addon plus an ergonomic API to provide access.

# Commands
- `bun run tools/build.ts all --backend cpu` build `whisper.cpp` binaries, a NAPI addon, compiled TypeScript, and tarball NPM packages for the wrapper JS package and the native addon package
  - e.g. on x64, Linux, and glibc, it would produce `spader-node-whisper-cpp-x64-linux-cpu-gnu-0.0.1.tgz` and `spader-node-whisper-cpp-0.0.1.tgz`
  - Use `--ci` to build architecture specific CPU backends as shared libraries (like what is shipped)
  - Use `NODE_WHISPER_CPP_BACKEND` to force a backend through the entire process. The precendence is:
    - `NODE_WHISPER_CPP_BACKEND`
    - `--backend`
    - Simple detection based on the system
- `bun run clean`
- `bun run model` downloads the tiny test model to `.cache/models` (override the directory with `NODE_WHISPER_CPP_MODEL_DIR`)
- `bun run fixtures:audio` regenerates the golden audio fixtures (requires `ffmpeg` and `python3` with `numpy`); the generated files under `test/fixtures/audio` are committed

# Testing
Tests are split into three tiers:
- `bun run test:unit` pure logic with no native addon or model. Audio decoding is verified against committed goldens generated by `ffmpeg`/`numpy`; backend logic runs against a fake addon selected with `NODE_WHISPER_CPP_ADDON`. Fast, runs anywhere.
- `bun run test:integration` loads the freshly built addon (via `NODE_WHISPER_CPP_ADDON`) and a real model, then transcribes `asset/jfk.wav`. Requires a prior `tools/build.ts addon` build and the model.
- `bun run test:smoke` installs the built tarballs into JS and TS consumer fixtures and transcribes real audio end to end.

`NODE_WHISPER_CPP_ADDON` overrides the addon path the loader requires; tests use it to select the fake or the built addon, and downstream consumers can point it at a custom build.

`bun run smoke` builds everything (`--ci`) and runs the integration and smoke tiers.

# Rules
- Always verify non-trivial changes with:
```bash
bun run clean
bun run test:unit
NODE_WHISPER_CPP_BACKEND=cpu bun run smoke
```
- If testing a specific backend, substitute it into the environment
- Never put logic in `package.json` scripts; every script should look like `bun run $script $args`
- Prefer to export a single top-level namespace rather than loose functions and types
